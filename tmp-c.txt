fix(memory): 修正关键词通道（pg_trgm 不支持中文）与事实时间缺失

## 🔴 发现一个设计缺陷：关键词通道对中文完全失效

docs/03 §17.4 的 C16 决定「关键词通道用 pg_trgm」，
理由是「按字符三元组匹配，无需分词器，适合中文」。**这个理由是错的。**

实测（PostgreSQL 18 + pg_trgm 1.6，见 audit/trgm-probe.sql）：

    SELECT show_trgm('用户住在杭州');   -- → {}      空集！
    SELECT show_trgm('hello world');    -- → {"  h"," he",...}
    SELECT show_trgm('2026年9月');      -- → {"  2"," 20",...}  只切了数字

pg_trgm 的解析器只把字母数字当词，CJK 全被忽略 → 不产生任何三元组
→ similarity() 恒为 0 → 混合检索退化成单路向量检索。
实测表现：检索诊断里 keyword 恒为 0。

替代方案全部排除：
  · tsvector：to_tsvector('simple','用户住在杭州') → `'用户住在杭州':1` 整句一个词元
  · pg_bigm / pgroonga / zhparser：不在 pg_available_extensions 里
    （镜像 pgvector/pgvector:pg18 只带 pg_trgm）

修法：新增 memory/chinese-ngram.ts，在应用层切字符 bigram，
用 LIKE 筛选 + 按「命中的不同 bigram 数 / 总数」打分（阈值 0.3）。
选 bigram 的理由：unigram 太宽（「的」几乎命中所有记忆），
trigram 太严（中文以双字词为单位，三字窗口会横跨词边界）。

实测修复后（真实库）：`雅思` → 关键词命中 1 条，`女朋友` → 1 条。
「换了说法」的查询（如「搬家」vs「搬到」）仍走向量通道 ——
这本就是两路互补的设计，也是需要 RRF 融合的原因。

⚠️ 这是对 C16 的**偏离**，需要修订文档：
   ① C16 的结论应改为「关键词通道由应用层 bigram 实现」
   ② memories 上那个 gin_trgm_ops 索引（idx_memories_content_trgm）
      对中文无用（索引里没有任何中文三元组），现在只是写入开销，
      应随修订一起删除 —— 那需要走 Schema 变更流程，本次保留不动

## 修正事实时间缺失（valid_from 被写成对话时间）

抽取契约原先没有事实时间字段，编排层只能把「对话发生时间」当 valid_from。
实测（真实模型）：
  用户说「我上周三从北京搬到杭州」
  → 事件正确记为 2026-09-16（模型换算了「上周三」）
  → 但记忆的 valid_from 被写成 2026-09-23（对话当天）
Agent 于是把搬家日期说成了 09-23 —— 它答错了，但错在数据不在它。

修法：抽取契约新增 validFrom 字段，要求模型在用户给出时间线索时填，
换算不出来就留空（语义是「自记录起有效」）。

刻意**不**用对话时间兜底：valid_from 属 C25 的不可变字段，写错只能重建记忆，
因此宁缺勿错。这与 eventTime 的处理同理（解析不出来就丢弃整个事件）。

## Agent 只读记忆工具（docs/02 §21）
新增 memory/tools.ts：search_memory / get_memory / get_timeline。

⚠️ **只实现只读的三个**。Q3 锁定「Agent 只读记忆，不持有写工具」，
save / update / delete 刻意不实现 —— 理由：让模型写记忆等于把
「什么值得长期记住」的判断交给它临场决定，而那个判断不可复现、
无法回归测试，且会绕过抽取流水线的幂等键、冲突判定与来源追踪。
已加测试逐个点名禁用那些写工具（写成显式列表而不是「不等于那三个」，
这样新增工具时会失败并要求人确认）。

工具设计上的两个刻意选择：
  · 结果**不带 id 与分数** —— 模型会引用它们（「根据记忆 m_abc123」），
    对用户毫无意义
  · get_memory 找不到时提示「不要向用户断言这条记忆不存在」——
    检索不到 ≠ 用户没提过

## 摘要接入 Life Review（docs/04 §32 的四条来源现在齐了）
摘要放在材料**最后**：它是最模糊的材料（对摘要再做一次压缩），
放最后让模型先看硬事实，避免以摘要为主干去写。

测试 315 项全通过（新增 22 项）。
真实模型验证：工具被正确调用（问搬家日期→调 get_timeline，
问猫名→不调工具直接用上下文），且能区分事件与目标。
