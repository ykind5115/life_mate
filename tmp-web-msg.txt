feat(web): 新增 Web 界面，不再需要用命令行聊天

## 为什么
用户反馈「不想每次聊天都用命令行，感觉跟工作一样」。
在此之前只有 API，日常使用只能靠 curl 或临时脚本 —— 那不是能用的形态。

## 形态选择：零构建步骤的单页界面
docs/02 §6 规定前端是 Next.js + React + Tailwind（Phase 7 的目标形态）。
本次**没有**按它做，理由是范围与阶段：
  · V1.0 目前只有 5 个页面、状态很少，构建链的收益还未体现
  · 目标是「现在就能用」，不是一个完整前端工程
因此用原生 HTML/CSS/ESM + Fastify 托管静态文件。
将来换 Next.js 时整体替换 public/ 这一层，API 与后端不用动。

## 唯一新增依赖：@fastify/static
自己读文件返回要手写路径穿越防护、Range、ETag、缓存头 ——
写错任一项都是安全问题。官方插件 21 个传递依赖，值得。

## 功能
- **对话**：SSE 逐字输出；显示「召回 N 条记忆 / 调用 N 次工具」，
  让用户看到它想起了什么（这是这个产品的核心体验）
- **记忆**：列表 + 语义搜索（走完整检索链路，带通道命中数）+ 删除/恢复
- **时间线**：按年月分组
- **目标**：列表 + 新增 + 完成/搁置/删除
- **回顾**：日/周/月，展示生成的回顾与材料来源统计
- **设置**：auto_extract 开关（含「已有记忆不受影响」的说明）
- 侧栏实时显示「已记住 N 条」，后台抽取有可见反馈

## 安全：所有插值都转义
页面渲染的是**模型输出**与**用户自己的记忆** —— 前者不可信，
后者是私密数据。因此一律走 textContent，唯一的例外是 renderMarkdown
（先整体转义再按白名单加标签）。

markdown.js 抽成独立的纯模块，这样它能被 Node 直接测试 ——
app.js 是浏览器脚本，测不了。新增 16 项测试，其中 6 项专门测 XSS：
script 标签、img onerror、代码块内的标签、属性逃逸、
以及「用户伪造 <strong> 假加粗」这种情况。

## 修掉的问题
- app.js 里 relTime 被重复定义（我的编辑残留），整个脚本 SyntaxError
  → 页面会完全空白。已修，并用 node --check 验证
- 列表正则里的 `(?:\n|$)` 会吃掉列表项后的换行，
  导致正文被渲染进 <ul> 里。已修并加回归测试

## 验证方式（需要说明）
- node --check：两个前端脚本语法通过
- 16/16 markdown 与 XSS 测试通过
- 12/12 静态资源与 API 端点检查通过（含路径穿越被挡、不暴露目录列表）
- 全部 DOM 选择器与 index.html 交叉核对通过
- ⚠️ **未在真实浏览器里打开过页面** —— 本环境的 headless Chrome
  无法产出输出。因此「渲染是否真的正确」需要你打开看一眼。
