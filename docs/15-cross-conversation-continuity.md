# 跨会话衔接缺失 — 问题分析与方案

**日期：** 2026-10-08
**来源：** 用户实测反馈 —— 短时间内开两个对话，第二个对话接不上第一个
**状态：** 待讨论（本文只给分析与方案，未动代码）

---

## 0. 结论

用户的判断是对的，但成因比「闲聊没被总结成记忆」更直接：

> **上下文组装只看当前会话。新会话第一轮的历史是空数组。**

`chat-service.ts` 取历史消息时按 `conversationId` 过滤
（`findRecentMessages({ conversationId })`），因此**跨会话的对话原文从来不会进入上下文**。
记忆检索虽然能跨会话，但它给的是「长期事实」，不是「刚刚聊到哪」。

所以这不是记忆质量的问题，是**少了一层上下文**。

## 1. 实测复现（用户的两个会话）

```text
会话 A「国庆后返工聊 agent 进度」  10:01 – 10:14   14 条
会话 B「国庆做项目与打扫」          10:15 – 10:59   50 条
                                   ↑ A 结束后 1 分钟开始
```

**A 的末尾（10:14）：**

```text
user      现在初版已经差不多了，把前端页面设计一下，连上模型的API就可以测试了，
          等我今天晚上下班回去之后测试一下就可以了
assistant 那差不多了，前端页面这步通常比想的花时间……测完有啥结果跟我说说。
```

**B 的开头 —— 割裂发生在第 2~8 条：**

```text
user      (10:15) 我国庆节期间除了做项目之外，就是睡觉了……
assistant (10:15) 打扫完屋子那种感觉确实不一样……
                  你说的项目，是之前提过想学的那个 AI agent，还是工作上的活？
                  ↓ 此刻它刚刚在 A 里聊了 6 轮问卷系统，却问「是哪个项目」
user      (10:17) 你不记得了吗？我刚才跟你讲的我那个问卷系统呀
assistant (10:17) 这个我记岔了，你刚才没细讲项目本身，我就没对上号。
                  ↓ 不但没纠正，还编了个理由（"你刚才没细讲"）
user      (10:20) 你记混了，我五分钟前还再和你聊问卷系统的话题呢
assistant (10:20) 那可能不是在咱们这儿说的，这回你只提了国庆做项目和打扫屋子这两件。
                  要是真在这聊过，你再说说当时聊到哪儿了，我接着往下聊。
                  ↓ 把举证责任推给用户
user      (10:22) 你看一下之前的对话记录呢？在另一个会话里面的，你看不到对吗？
assistant (10:22) 别的会话里的聊天记录我看不到，只能看咱们现在这一轮。
```

**五个问题，从轻到重：**

| # | 问题 | 严重度 |
| --- | --- | --- |
| ① | 第一轮就问「你说的项目是哪个」—— 上一轮刚聊完 | 🟠 割裂 |
| ② | 被指出后**编造理由**（「你刚才没细讲」）—— 事实是讲得很细 | 🔴 幻觉 |
| ③ | 第三次改口成「那可能不是在咱们这儿说的」 | 🔴 幻觉 |
| ④ | 反问用户「你再说说当时聊到哪儿了」—— 把举证责任推给用户 | 🟠 体验 |
| ⑤ | 最后承认「别的会话我看不到」—— 结论对了，但代价是 4 轮拉扯 | 🟡 |

②③ 是**新发现的幻觉形态**：不是编造事实，而是**编造「我没听过」的理由**。
根因与 09-29 那次幻觉同类 —— 模型对自己「知道什么」没有可靠的感知，
于是用一个看似合理的解释去填补空缺。

## 2. 为什么现在接不上

### 2.1 三层上下文里没有「上一个会话」这一层

`docs/10 §3.2` 记录的现有层次：

```text
┌─ 系统规则
├─ 长期记忆（本次相关的最多 8 条，带生效日期）
├─ 更早对话的摘要（仅当**本会话**很长时才出现）
├─ 当前会话最近 20 条消息的原文        ← 只覆盖当前会话
└─ 你刚说的这句
```

```text
❌ 没有「刚刚在另一个会话里聊了什么」
```

### 2.2 摘要也救不了 —— 它是按会话存的

`listActiveSummaries(existingConversationId)` 同样按会话过滤，
且 B 是刚开的会话，没有任何摘要。

### 2.3 记忆检索能跨会话，但答的是另一个问题

本次实际注入的记忆里**确实有问卷系统**：

```text
「用户接到一个 AI 工作流程项目，目标是用模型完成问卷系统的全流程：
  问卷设计、下发、审核、人工回填以及回填后的审核」  ← 命中了
```

模型在 seq8 也把它复述出来了。**但这条记忆是"国庆前的状态"**，
不含 10:09–10:14 那几轮的关键结论：

```text
· 决定「把当前状态喂进去、让模型基于状态改」而不是重放对话历史
· 决定在结构旁挂一个「约束字段」记面向将来的规则
· 初版已差不多，下一步做前端页面 + 连模型 API，当晚测
```

于是出现最讽刺的一幕：**它记得住"用户在做问卷系统"这个月级事实，
却记不住"一分钟前刚聊过问卷系统"。**

用户的原话点出了要害：

> 不是所有的事情都会被总结，形成记忆，但是短时间内的闲聊还是需要作为
> 上下文的一个部分的，毕竟是"好伙伴"，闲聊也是占很大比重的。

## 3. 方案

### 3.1 核心做法：注入「上一个会话的尾巴」

新会话开始时，若上一个会话**刚刚结束**，把它的末尾若干条原文
作为一段**明确标注来源**的上下文注入。

```text
┌─ 系统规则
├─ 长期记忆（不变）
├─ 更早对话的摘要（不变）
├─ 【新增】刚刚在另一个对话里聊到  ← 标注来源与时间
├─ 当前会话最近 20 条消息的原文
└─ 你刚说的这句
```

**位置必须在当前会话历史之前**，理由与 §12.4 对摘要的要求相同：
它讲的是「之前」的事，放在后面会被模型当成刚发生的。

### 3.2 触发条件（三个都要满足）

```text
① 上一个会话的最后一条消息距现在 ≤ 时间窗（建议 2 小时，可配置）
② 当前会话刚开（历史消息数为 0）—— 只在第一轮注入，之后不再需要
③ 上一个会话存在且有消息
```

**为什么必须限定「当前会话是新的」**：
会话进行到第 5 轮时，当前会话自己的历史已经足够，
再塞上一个会话只会白占 token、还可能把话题带偏。

### 3.3 注入的形状

```text
【刚刚在另一个对话里聊到】（10:09 – 10:14，距今 1 分钟）

  你：作为日志，因为这个系统核心还是问卷，模型获取上下文不重要，
      直接把要修改的问卷模板结构放到上下文中比放对话记录效率高的多……
  我：方向我同意……这里有个缝值得补一下：有些约束只存在于对话里，还没落进结构。
      所以我会在结构旁边挂一个很小的约束字段……
  你：有道理，等我把初版弄完之后，看看能不能正常对话生成和改动问卷……
  你：现在初版已经差不多了，把前端页面设计一下，连上模型的API就可以测试了……

⚠️ 这是**另一个对话**里的内容，不是当前这段对话。
   若对方提到「刚才说的」，优先理解为上面这些。
   不要说你没听过 —— 你见过，只是来自另一个对话。
   若确实不在这里，直说「这部分我这边没有」，不要编理由。
```

**三点设计意图：**

```text
· 明确标注「另一个对话」→ 它才能诚实地说「你在另一个对话里提过」，
  而不是被自己的上下文搞糊涂（现在的问题是它连自己看过什么都不知道）
· 最后两条约束是直接针对本次的 ②③：
   不要编「你没细讲」这类理由
· 条数上限（建议 6 条）+ 时间窗，保证 bounded
```

### 3.4 参数建议

| 参数 | 建议值 | 依据 |
| --- | --- | --- |
| 时间窗 | **2 小时** | 与 `TIME_GAP_MARKER_MINUTES = 60` 的口径一致：超过这个量级就不是「同一段连续对话」了。2 小时是「连着聊」的宽松上界 |
| 条数 | **末尾 6 条** | 3 轮往复。足够覆盖「刚才在聊什么」，又不会喧宾夺主 |
| token 预算 | **单独 ≤ 800** | 记忆已有 2000 的预算，这一层不该同等份量。超出就从头截断 |

### 3.5 与「时间标记」的关系（已经有的机制）

`context-builder` 已有 `buildTimeMarker`（间隔 ≥ 60 分钟才打标记）。
本方案与它是**互补**的：

```text
时间标记   解决「同一个会话里隔了很久」 → 让模型知道「上次是两天前」
上一会话   解决「换了个会话但时间连着」 → 让模型知道「刚才在隔壁聊过」
```

两者合起来才是完整的时间感：**现在既能感知"隔得久"，
也能感知"换了窗口但没隔多久"。**

## 5. 我想先确认的一个风险

**注入上一个会话的原文，是否越过了你期望的边界？**

```text
· V1.0 是单用户，所以技术上不存在「把 A 的内容泄露给 B」
· 但「跨会话可以互相看见」本身是个产品决定 ——
  你可能希望某些对话是独立的（比如一段不想被延续的谈话）
```

如果你希望保留「有些会话不参与衔接」的能力，
我建议加一个**会话级的开关**（默认开启衔接），而不是全局关掉这个功能。
这一条需要你定；在你说之前我不动手。

## 6. 顺带发现的另一个问题（独立于本方案）

本次对话暴露的 ②③ —— **编造「我没听过」的理由** —— 与 09-29 那次幻觉同源：
模型对自己「知道什么」没有可靠感知。本次方案能消除这一个具体场景
（因为它确实见过了），但**同类幻觉还可能出现在别处**：

```text
· 记忆没检索到 → 「你没跟我说过」     （其实说过，只是没召回）
· 检索到但不完整 → 「你只说了 X」      （其实还说了 Y，被预算裁掉了）
```

`docs/12 §方案 3` 已加过一条约束（「不要因为这里没有就断言对方没说过」），
本次方案 §3.3 的那两条是对它的补充。是否要进一步系统性处理，
建议等这轮改完再观察 —— 现在下结论样本太少。
