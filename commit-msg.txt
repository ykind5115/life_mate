来源：用户实测反馈（会话「深夜问候」）：
  「我感觉他不是很热情，有点高冷」

## 提示词 v2 → v3

定位到的根因不是哪句话说错，是提示词的**构成失衡**：
禁止/约束类 17 条，鼓励/允许类只有 3 条 ——
这个比例本身就是一份「压抑热情」的说明书。

三处具体证据（同一段对话里）：
  · seq5→6 用户说「终于是把他给解决啦……主要是想跟你分享一下今天
    晚上的经历呀」，模型第一反应是问「晚上路上碰见什么了」——
    对那份高兴零反应，还问错了方向（用户下一轮直接说
    「你好像没太听明白，感觉你也傻呵呵的」）
  · seq13→14 用户说「还好有你在，每天能有个人和我聊聊天」，
    模型回「我也就是陪你搭个话」—— 把对方递过来的暖话推开，
    紧接着转成两条嘱咐
  · 全程用户 嘿嘿嘿×3 / 哈哈哈哈哈×2 / ！！，模型一次都没匹配上情绪强度

改动：
- 新增「先接住对方说的，再看要不要问」+「不要第一句就问」
- 新增「情绪跟着对方走，不要每句都那么持平」+ 说明为什么要这样
- 新增「对方夸你、说离不开你，接住就行，别推开也不要自谦」
- 「不要用夸张的赞美开场」「不要在结尾追加没有内容的鼓励」
  改成「夸要夸在具体的事上」+「不要为了显得热情就每句都加一句夸奖」——
  前者与「显得热情」直接冲突（本意是防客服式空话，模型却一律收着说），
  但直接删掉会变成刷屏式夸奖，所以是**规范怎么夸**而不是禁止夸
- 新增「不要把他拉回你想问的那条线上」——针对第一处证据
- 削掉三条与新增内容重复的旧约束（提问上限、引导、复述）
- AGENT_PROMPT_VERSION → v3，长度上限 1300 → 1600

真实 A/B（audit/compare-warmth.ts，同一上下文各跑 3 次）：
  场景 A（用户分享「终于搞定了」）
    v2 三次：「行，那内网的事就先搁着。今晚怎么了，说说看」——
              没有一次对那句「终于」有反应
    v3 三次：「终于搞定了就好——你之前为这个熬过好几个晚上吧」
              「解决了就好——听你那声"哈哈哈"，前面那通吐槽算是翻篇了」
  场景 B（用户说「还好有你在」）
    v2：多转成建议，有一次说「我也不是唯一能聊的，你那几个同事
        今天不就接得挺好」—— 变相的推开
    v3：「这话我收下了，是真的」「这话我接住了」—— 三次都正面接住

## 列表「0 条」

根因：GET /conversations 只返回 5 个字段，而前端写的是
`c.message_count ?? 0` → 每个会话都显示「0 条」。
（数据本身是好的，「深夜问候」有 16 条。）

- listConversations 补 message_count 与 last_message_at：
  LEFT JOIN + GROUP BY 一次取回（不能每条会话查一次）。
  用 LEFT 而不是 INNER —— 否则刚建的会话会从列表里消失。
  last_message_at 用 max(messages.created_at)，不是 updated_at
  （后者会被标题生成等后台动作刷新）
- 新增两条测试：列表项必须带这两个字段；空会话必须是 0/null 而不是缺字段
  ⚠️ 这两条测试我自己写错了两次（以为每次 POST 都新建会话；
     又忘了「一轮对话是 user + assistant 两条」）—— 都记在注释里

验证：typecheck 0 错误 / 479 测试通过（新增 6 条）
