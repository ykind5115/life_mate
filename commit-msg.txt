feat(voice): 语音转文字 —— 录完确认再发，不改动记忆系统

用户需求原话：「其实我就想做一个语音转文字的功能，一直打字感觉有点累」。
按此定位：这是**输入方式**，不是语音助手（无 TTS、无语音唤醒、无连续对话）。
闭环：录音 → 转文字 → **填进输入框等确认** → 用户按发送 → 走现有对话接口。

## 为什么中间必须停一下让用户确认

STT 一定有错字，而错字进了对话就会进记忆抽取 ——
「张三」听成「张散」，那条记忆就永久错了，而记忆是要长期依赖的。
所以后端只返回文本、不落库，前端只填输入框、不自动发送。
「不需要改造现有记忆系统」就是靠这一点成立的。

## 本地部署（用户选定）

浏览器自带的 Web Speech API 在中文下依赖服务端识别，音频会离开本机；
而这个记忆库里全是前女友、工资、面试、加班吐槽这类事。
因此用本地 Whisper 容器，音频不出这台机器。

- docker-compose 新增 stt 服务（onerahmet/openai-whisper-asr-webservice，
  large-v3-turbo，只绑 127.0.0.1:9000，GPU）
  默认不用 faster-whisper 变体：那需要同时设 ASR_ENGINE，少一个必须配对的
  变量 = 少一种起不来的方式。而 large-v3-turbo 本身已经够快。
- .env.example 补 STT_* 五个变量

## 浏览器侧转换，服务端不需要 ffmpeg

MediaRecorder 给的是 webm/opus，Whisper 要 WAV。
用 OfflineAudioContext 在浏览器里重采样成 16kHz 单声道 ——
零依赖，且把「格式归一」放在数据产生的地方。

## 不引 @fastify/multipart

只传一个音频文件，multipart 是杀鸡用牛刀。
改成正文直接是音频字节 + Content-Type，用 Fastify 原生的
addContentTypeParser（parseAs: 'buffer'）—— 零新增依赖。
代价是不能同时传多个字段，但我们只需要一个音频。

## 拒收逻辑（这些的失败方式是静默的坏结果，不是报错）

- src/shared/wav.ts 自己解析 WAV 头（40 行，不引音频库）
   · 非 PCM / 声道异常 / 采样率异常 / 位深异常 → 明确拒绝
     （放过去 = 把没预期的输入交给 Whisper，它会对着噪音
      吐出一段看着像文本的幻觉）
   · 时长按**实际剩余字节**算，不按 data 块声明值 ——
     录音被中途打断时声明值偏大
- 超过时长/大小上限 → 413 并告知「录了多久、上限多少、分几次说」
  刻意**不截断**：截断后 Whisper 对着半句话输出看似合理的文本，
  而用户以为那是自己说的全部

## 前端

- public/recorder.js：录音 + 重采样 + 编码 WAV
- 麦克风按钮：只有 STT 可用时才显示（服务没起来就不显示，
  而不是显示一个点了会报错的按钮）；录音中变红呼吸 + 计时；
  按 Esc 放弃；转写完**追加**进输入框（不覆盖已打的内容）并聚焦
- GET /transcribe/status 供前端判断可用性

## 顺带修了两个我自己犯过的错

1. recorder.js 里写了 TypeScript 语法 —— 前端零构建，浏览器直接加载
   public/*.js。这个错我在 core.js 上已经犯过一次（2026-10-08），
   这次又犯了。因此新增 src/web-build-free.test.ts：
   用 node --check 逐个检查 public/*.js，并有一条「故意塞 TS 语法
   应当被抓出来」的测试守测试工具本身。
   人不会因为犯过一次就不再犯，所以改成让机器每次检查。

2. 测试夹具自己不自洽：silence(1) 固定按 16kHz 生成 16000 个采样，
   却在 8kHz 下编码 → 得到 2 秒音频，然后断言「时长应当是 1 秒」失败。
   夹具与断言必须用同一个采样率。

验证：typecheck 0 错误 / 506 测试通过（新增 27 条：WAV 15、路由 9、
      前端零构建 3）
未验证：真实转写效果 —— whisper 容器还没起，需要镜像拉下来后手工确认。
       GET /transcribe/status 现在返回 available=false 是对的。
